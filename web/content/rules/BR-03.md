## Definition

BT-2 is the invoice issue date. It must be present, and its format is fixed
by the syntax binding — this rule fires both when the element is missing and
(in the CII case in practice) when its format attribute is missing or wrong,
because the wrong format usually reads as no date at all to a strict parser.

## Common causes

- **The element is absent** because a "draft" document was passed through a
  pipeline that only sets the issue date at final approval, and the
  intermediate document was submitted for validation (or accidentally sent)
  before that step ran.
- **CII: `format="102"` attribute forgotten.** CII dates are strings, not
  native XML dates, and need an explicit format code; `102` means
  `CCYYMMDD`. Some implementations write the date correctly but omit the
  `format` attribute, which several validators — not all — treat as
  equivalent to a missing date.
- **UBL date not in `YYYY-MM-DD`.** UBL uses `xsd:date`; a locale-formatted
  string like `31/08/2026` or `08-31-2026` fails to parse as a date at all
  rather than producing a "wrong date" — it reads as absent.

## How to fix it

- **UBL**: add `cbc:IssueDate` in `YYYY-MM-DD` format
  (e.g. `2026-08-31`).
- **CII**: add `ram:IssueDateTime/udt:DateTimeString` with `format="102"`
  and the value as `CCYYMMDD` (e.g. `20260831`), under `rsm:ExchangedDocument`.

## Example

### UBL — wrong

```xml
<Invoice ...>
  <cbc:ID>INV-2026-0001</cbc:ID>
  <!-- IssueDate missing -->
  ...
</Invoice>
```

### UBL — correct

```xml
<Invoice ...>
  <cbc:ID>INV-2026-0001</cbc:ID>
  <cbc:IssueDate>2026-08-31</cbc:IssueDate>
  ...
</Invoice>
```

### CII — wrong

```xml
<ram:IssueDateTime>
  <udt:DateTimeString>20260831</udt:DateTimeString>  <!-- format attribute missing -->
</ram:IssueDateTime>
```

### CII — correct

```xml
<ram:IssueDateTime>
  <udt:DateTimeString format="102">20260831</udt:DateTimeString>
</ram:IssueDateTime>
```
