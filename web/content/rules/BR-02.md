## Definition

BT-1 is the invoice number: a unique identifier assigned by the seller. It
must be present — this is one of the most basic identity fields on the
document.

## Common causes

- **The element is present but empty** (`<cbc:ID></cbc:ID>`), typically
  because a numbering sequence generator returned `null`/`undefined` and the
  templating layer serialized it as an empty tag rather than failing loudly.
- **Confusing the invoice number with an internal/database primary key** and
  populating a different, non-business identifier field instead of `cbc:ID`.
- **Batch generation writing the number to the filename only**, on the
  assumption that the filename is sufficient — the filename carries no
  meaning to a downstream consumer or archive; the number must be inside the
  document.

## How to fix it

- **UBL**: add `cbc:ID` as a direct child of the document root
  (`Invoice`/`CreditNote`), holding the seller's invoice number, non-empty.
- **CII**: add `ram:ID` under `rsm:ExchangedDocument`.

## Example

### UBL — wrong

```xml
<Invoice ...>
  <cbc:CustomizationID>urn:cen.eu:en16931:2017</cbc:CustomizationID>
  <cbc:ID></cbc:ID>  <!-- empty -->
  <cbc:IssueDate>2026-08-31</cbc:IssueDate>
  ...
</Invoice>
```

### UBL — correct

```xml
<Invoice ...>
  <cbc:CustomizationID>urn:cen.eu:en16931:2017</cbc:CustomizationID>
  <cbc:ID>INV-2026-0001</cbc:ID>
  <cbc:IssueDate>2026-08-31</cbc:IssueDate>
  ...
</Invoice>
```

### CII — correct

```xml
<rsm:ExchangedDocument>
  <ram:ID>INV-2026-0001</ram:ID>
</rsm:ExchangedDocument>
```
